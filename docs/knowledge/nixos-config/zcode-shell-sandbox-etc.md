Tool shells in ZCode sessions on yoga run sandboxed inside the ZCode fhsenv: `/etc/systemd` is bind-mounted from `zcode-…-fhsenv-rootfs` (findmnt shows it), `sudo` is blocked by `no_new_privileges`, and `/proc/1/root` is inaccessible. Checking live host config files (e.g. `/etc/systemd/sleep.conf`, `systemd-analyze cat-config`) from an agent shell gives wrong answers — this misled diagnosis once (2026-09-07). Host truth comes from: `journalctl`, `/run/current-system` and `/run/booted-system` store paths, `/sys` (passes through), and upower history in `/var/lib/upower/` (battery telemetry: `history-charge-L21D4PE0-70-3199.dat`, tab-separated, comma decimals, epoch timestamps). Also useful: `/proc/uptime` discriminates hibernate resume (excludes power-off time) from an in-place abort. What works inside the sandbox (verified 2026-09-09): `fwupdmgr refresh`/`get-updates` (network allowed), `nix eval`/`nix build`/`nixos-rebuild dry-build` against the local flake, `journalctl -b`, and reads of `/sys` + store paths. Verified 2026-09-30: read-only `virsh -c qemu:///system` commands work from the sandbox unprivileged (dk is in the libvirtd group) — `net-list --all`, `list --all`, `dominfo`, `dumpxml`, `net-info` all fine = host-truth source for VM/network state; `virsh net-dhcp-leases` also usable. Unreadable: `/var/log/libvirt/qemu/*.log` (mode 600 root), `/proc/<daemon-pid>/environ` of system daemons (Keine Berechtigung even for a read-only PATH check — 2026-09-30, libvirtd), and `/var/lib/libvirt/network/` (doesn't exist — state actually lives in `/var/lib/libvirt/dnsmasq/` and `/var/lib/libvirt/qemu/networks/`). What needs the user's sudo instead: `btrfs inspect-internal map-swapfile` (swap dir is 0700) and `dmesg` (host `dmesg_restrict`; `journalctl -k` from the user's own shell is the equivalent when the user pastes output). Also: `uptime -p`/`uptime -s` error out on this host despite being documented — compute resume gaps from `cat /proc/uptime` + `date` instead. `/run` is NOT writable from the sandbox (e.g. `/run/yoga-s2h-decision` → Keine Berechtigung) though reads pass through — to behaviorally test scripts with hardcoded `/run` state files, copy to /tmp and `sed`-repoint the path variables (worked 2026-09-09 for the yoga-s2h recheck A/B test: new script vs the still-deployed old one at `/run/current-system/etc/systemd/system-sleep/...`, which is readable and makes a perfect control). `nix store diff-closures` between `/run/current-system` and a freshly built toplevel also works in the sandbox and is the strongest pre-rebuild QC gate (caught a package-loss regression eval checks missed). Documented in REPO_OVERVIEW.md Known Gotchas too. Agent shells also inherit the live session's `WAYLAND_DISPLAY` (wayland-1), so wayland clients run against the user's actual session: `XDG_RUNTIME_DIR=/run/user/1000 nix run nixpkgs#grim -- /tmp/screen.png` takes real screenshots (the Read tool renders the PNG — ground truth for UI debugging), and quickshell test instances (`qs -p <config> -n` as a background task with the unit's envs) render live UI on the user's screen with console.log streaming back to the agent — used for dkbar click debugging 2026-09-22. NixOS QC techniques verified 2026-09-22: attr names containing dots (e.g. `config.systemd.user.units."dms.service"`) cannot be addressed through `.#flake-path` quoting — eval them via `--apply` on the parent attr (`nix eval --json .#nixosConfigurations.yoga.config.systemd.user.units --apply 'u: u."dms.service".text'`), and build arbitrary config sub-attrs with `nix build --impure --expr '(builtins.getFlake (toString /home/dk/nixos-config)).nixosConfigurations.yoga.config.…'` (getFlake on a local path needs --impure; `nix build` has no --apply flag). Building `config.environment.etc."systemd/user".source` yields the REAL generated unit tree (package-unit symlinks + `*.service.d/overrides.conf` drop-ins) — ground truth for unit-merge questions that evaluating unit text alone can mislead on. `XDG_RUNTIME_DIR=/run/user/1000 systemctl --user show-environment` returns the live user-manager environment (what a unit started now inherits — used to confirm the uwsm-imported PATH incl. /run/current-system/sw/bin). `nix eval github:nixos/nixpkgs/<rev>#…` can fail transiently with "HTTP/2 stream reset" — retry or eval from the local flake instead.
