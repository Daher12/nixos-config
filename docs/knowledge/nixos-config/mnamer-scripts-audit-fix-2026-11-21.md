**mnamer 2.6.0 source facts (the load-bearing semantics):**
- batch mode with ZERO API hits falls back to filename-parsed metadata: `match = matches[0] if matches else target.metadata` — unmatched files get MOVED under guessed names. `--no-guess` skips them instead (skips are NOT failures — exit 0, just counted). This was the junk-in-libraries mechanism: `no_guess` defaulted false and media-import runs the plain `import` verb.
- `ignore` regexes match the FULL ABSOLUTE PATH via `re.search(pattern, str(path), re.IGNORECASE)`; paths are absolute from `crawl_in` (os.walk, recurse walks everything). So anchored patterns like `^RARBG.*` NEVER match (paths start with `/`), and path-scoped excludes like `.*/kinder/.*` work.
- Destination = `movie_directory` + formatted format-string split on separators; parents `mkdir -p`ed — slashes in `movie_format` valid.
- Providers: TvMaze (default episode_api) sends NO language, not localized, English-primary catalog → German kids releases ("Feuerwehrmann.Sam") find ZERO hits. TVDb honors `language=de` in search AND ships a bundled key (`E69C7A2CEF2F3152` in providers.py) — free German lookups, no secret. TMDb honors language (bundled key too). OMDb neither. mnamer's episode_api enum = {tvdb, tvmaze} only.
- Config file keys = CLI long args with dashes→underscores (snake_case — module was already correct); `replace_before`/`replace_after` are config-file-only keys; file may be named anything via `--config-path` (upstream default name is `.mnamer-v2.json`).

**QC ROUND 2026-11-21 (same day, user-prompted "quality control") — 3 more defects found+fixed, all PRE-EXISTING, found by behavioral simulation with a mocked mnamer-tools (fake verb logger/mover) driven through a pty:**
1. **confirm() read -q newline poisoning (THE big one)**: zsh `read -q` returns on the y KEYPRESS and leaves the user's Enter in the tty buffer; the NEXT read -q reads that newline as "n" and silently auto-declines. Empirically proven human-paced through a pty (y\ny\n → second prompt got ^J). Consequence in the old flow: confirm kinder with y+Enter → main import confirm auto-declined → "nothing imports" — a second, independent root cause for the user's original symptoms. A drain-after-read fix CANNOT work (Enter arrives ~300ms after the y, after any drain timeout). FIX: confirm() now uses a full line read `read -r "reply?$1 [y/N] "` + `[[ $reply == [yY] ]]` — always consumes its newline, works piped too (harness no longer needs a pty). One extra keypress (Enter) is the UX cost.
2. **`print "--test: …"` = `bad option: -t`**: print parses the leading --test as options → error line in every --test run at both sites. FIX: `print -- "--test: …"`.
3. **--test stopped after the kinder preview** (early return) — main import-test never ran, contradicting the documented "--test: download + extract + import-test only". FIX: TEST_ONLY no longer returns in the kinder block; both previews run, then `print -- "--test: main import skipped"`.
