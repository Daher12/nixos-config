**2026-09-21 evening — DMS runtime-settings architecture (reverse-engineered from 1.6.1 binary + live IPC), desktop polish round:**
- **Two stores, both prune default-equal keys:** `~/.config/DankMaterialShell/settings.json` = SettingsData (fontFamily/textRenderType/osdPowerProfileEnabled/barConfigs…); `~/.local/state/DankMaterialShell/session.json` = SessionData (**night+theme automation AND the night master switch live here**, plus launcher history). Editing the wrong file = keys silently dropped at next start. File edits require `systemctl --user stop dms` first (loads once at startup).
- **IPC truth:** `dms ipc list`; `settings` target has `get/set/dump/dumpSession` (set rejects unknown keys → SETTINGS_INVALID_KEY). Docs' `night automation/schedule` functions DON'T exist in 1.6.1's `night` target (newer-docs fiction). Go-core targets (theme.auto.*, wayland.gamma.*) = "Target not found" — not registered in this build; dgop is metrics-only (cpu/mem/disk CLI).
- **Night-mode quirk (1.6.1 initial-enablement bug, fixed upstream later):** runtime `night enable` sets the master but does NOT trigger period re-evaluation or gamma application. Protocol that works: write session.json (`nightModeAutoEnabled: true, nightModeAutoMode: "time", themeModeAutoEnabled: true` + `nightModeEnabled: true` master) → restart dms → initial evaluation runs and applies. Verified live: "Period: night, Current temperature: 4500K", next transition 05:00 (= 06:00 boundary − 60-min fade lead). Schedule semantics: sunset = StartHour, sunrise = EndHour (defaults 18/6 = night 18→06). CC nightMode widget = master toggle — turning it off kills automation.
- **Working state:** night auto 18–06 @4500 K + themeModeAuto (light 06–18) + textRenderType=2 (Native rendering, crisper bar text; Inter Variable font verified installed via pkgs.inter) + osdPowerProfileEnabled=false (power-profile OSD/UI off; runtime value confirmed false via `settings get` — pruned from file as default-equal). All persisted → survives reboot.
