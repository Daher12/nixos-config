Incident night 2026-09-15/16: after flake-update commit 152967f (linux-firmware 20260810→20260910, linux-zen 7.2.3→7.2.4-zen2), yoga freezes when the screen blanks/locks, then black-screens and boot-loops. Root cause confirmed upstream (RH Bugzilla 2532947): linux-firmware 20260910 ships a regressed `yellow_carp_dmcub.bin` (155115→154746 bytes; yoga GPU = YELLOW_CARP 0x1681, Rembrandt). Boot log signature: "failed to load ucode DMCUB(0x3F)" + "Error getting DMUB FW meta info: 4", error storm when DPMS-off hits. Gens 137 and 138 are package-identical (diff-closures empty) → audit commit 8468fe2 exonerated; kernel 7.2.4-zen2 likely fine. Gen 136 (7.2.3-zen1 + fw 20260810, nixpkgs 93108a5) = last known-good, still GC-rooted and in boot menu. 138 is boot default; user manually boots 137 to troubleshoot — works until display idles (kill trigger = blank/lock/idle s2idle). Firmware enters via `hardware.enableRedistributableFirmware` (modules/hardware/default.nix). No fixed firmware release exists yet (as of 2026-09-16). Fix: user rode gen 136 (verified good: DMUB 0x0400004C, zero errors) until 2026-09-17, then asked for the pin. IMPLEMENTED 2026-09-17, staged uncommitted on main: flake input `nixpkgs-firmware-pin` = rev 93108a538f079596c9a16c72cf03e9322782b6dd (previous lock rev) + overlay in `colloidFluentOverlays` pinning `linux-firmware` to its 20260810 snapshot (all hosts). QC green: firmware aggregate resolves yellow_carp_dmcub into the 20260810 store path; yoga toplevel builds with kernel 7.2.4-zen2 + fw 20260810 as only firmware; `nix flake check` exit 0; REPO_OVERVIEW got a Known Gotchas entry with removal condition. PENDING: user commit + `nixos-rebuild switch --flake .#yoga` + reboot. Drop input+overlay when fixed fw (>20260910) is in nixpkgs. Status update 2026-09-17 (later session): the pin was observed staged on branch `testing` (body above says main — trust the branch, `testing`), sharing the git index with the latitude-disko/opencode and Hyprland work (see [[latitude-disko-opencode]], [[hyprland-dms-setup]]); the overlay line was rewritten to `inherit (firmwarePinPkgs) linux-firmware;` because statix's assignment-vs-inherit gate fails the original form (behavior identical).
