Lucid restart crash-loop 2026-10-10 (3 dumps in `~/.cache/quickshell/crashes`, PIDs 398251/398449/398649, died seconds after start; 4th attempt survived): ALL three crashed inside `IconImageProvider::requestPixmap` — quickshell 0.3.1 calls the thread-unsafe Qt icon machinery (`QIcon::fromTheme`/`QIcon::pixmap`) with NO locking, reachable from BOTH the main thread (sync IconImage loads — e.g. lucid dock `DockItem.qml` has no `asynchronous: true`) and the QQuickPixmapReader thread (async loads — patch-111 tray/badge/notif sites). Crash signatures: 2× SIGSEGV in QSvgIconEngine (tryLoad/detach_helper) on the main thread via dock appListModel append ← HyprlandToplevel update; 1× SIGABRT `__cxa_pure_virtual` in `QPlatformPixmap::fromFile` on the reader thread. Known upstream bugs #1007/#1028/#1056/#1079, still unfixed in master (verified).

**FIX (executed, QC green, STAGED):** `quickshell-patches/201-iconprovider-thread-safety.patch` — QMutex + QMutexLocker serializing `requestPixmap` (upstream file at pinned rev 5d5d498 fetched verbatim, diff -u with a/ b/ labels, nixpkgs default patchFlags -p1 applies it on `passthru.unwrapped`). Proof it's in the binary: objdump of shipped `.quickshell-wrapped` shows `lock cmpxchg` against `(anonymous namespace)::requestMutex` inside requestPixmap; debug file at `lib/debug/quickshell` is symbols-ONLY (objdump -d empty) — disassemble the real binary at the nm address instead.

**⚠️ withModules closure trap (cost an hour):** quickshell `default.nix`'s `passthru.withModules = modules: wrapper.overrideAttrs {...}` closes over the ORIGINAL `wrapper` let-binding — `(pkg.overrideAttrs f).withModules m` silently DISCARDS the override (eval kept returning stock drv `h0vpp1c0`, patches=[]). Also the wrapper is a SEPARATE derivation (`cp -r ${unwrapped}/* $out`), so package-level patches can never reach the binary. Fix = patch `qs.unwrapped` + replicate the ~15-line wrapper verbatim with qt5compat folded into buildInputs (now in flake.nix overlay, heavily commented). This refines the older memory note "withModules does NOT chain — one list call" — the mechanism is closure capture, not chaining semantics. `nix eval .#nixosConfigurations.<h>.pkgs.*` is NOT the module pkgs (no overlays) — verify via `config.environment.systemPackages` instead; `_module.args.pkgs` is not evaluable.

**OUTCOME (user switched + restarted 2026-10-10 15:22, PID 530750): STABLE BUT ICONS DEAD.** The mutex converted the SIGSEGV into a HANG — the QQuickPixmapReader thread wedged inside the first serialized requestPixmap and every later async icon request queues behind it forever: silent Fluent→monogram fallbacks in dock/launcher/menus, ZERO "Could not load icon" warnings, shell responsive. Attribution proof: the 13:31 build (identical minus the mutex) crash report shows themed SVGs actively resolving; wrapper strings-diff old-vs-new byte-identical except qt5compat. LESSON: a mutex around a thread-unsafe API serializes but does not LEGALIZE cross-thread use — after a threading fix, "no crashes" is not success; verify the payload too (icons actually resolving). Rework plan (GUI-thread marshaling, drop the mutex) APPROVED + handed off same evening → [[lucid-date-iconwedge-2026-10-10]].
