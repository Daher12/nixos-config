Diagnosis/repair of "iTunes slow or no start" in the windows11 VM (started 2026-10-01):

- **Disk/virtio exonerated** (the earlier checkup's suspicion): 4K random uncached reads p50 0.21 ms / p99 0.59 ms, sequential write 473 MB/s; virtio-win 285 drivers all OK; host XML optimal; no disk errors in event logs.
- **Root cause NOT install corruption — proven by Phase 4 (2026-10-01 21:40–21:55).** After a pristine single-build reinstall (below), iTunes still hangs windowless. Three launch methods: (a) `schtasks /create /it` + `/run` — iTunes never appeared in the process list at all for 120 s (TaskScheduler operational log disabled, so task-side verdict unknowable; no iTunes crash/WER events — this trick is NOT reliable here); (b) headless SSH `Start-Process` — alive 30 s+, hwnd=0, CPU frozen at 0.89 s, 21 threads (round-1 signature); (c) console-session launch via windows-mcp App tool — pid 7384, no window for 125 s, CPU frozen 0.4375→0.4531 s, Responding=True. **Key socket evidence: 2 ESTABLISHED connections on port 27015 with NO Listen socket** → iTunes reached AppleMobileDeviceService, the service accepted (or its listener vanished), and never replies — matches round-1's 3 threads in EventPairLow waiting on an ALPC reply from AMDS. MCP screenshot confirmed zero iTunes windows on the console desktop. **Prime suspect: the AMDS service side is wedged (Running but dead), possibly stuck in device enumeration.** Supporting: `%LOCALAPPDATA%\Apple Computer\iTunes\iPodDevices.xml` (a device was known to this machine); USB hostdev 14cd:1212 passthrough + 2 spicevmc redirectors remain untested leads — but VM config is off-limits per user rules.
- **Per-user data state (P5 step 1 scope reduced)**: user already renamed the Roaming side on 2026-09-30 — `%APPDATA%\Apple Computer\iTunes` now holds only `Cookies` + `iTunes.bak-20260930`, so prefs are effectively fresh. The untested half is `%LOCALAPPDATA%\Apple Computer\iTunes` (`Cache.db`, `iPodDevices.xml`, `VersionCheck.plist`). Real iTunes library location still unknown (default Music\iTunes was empty).
- **Gated repair history** (user mandates: stop at every GATE, bound every command, msiexec logs to `C:\Temp\apple\*.log`): P1 partial install confirmed → P2 both `msiexec /x` exit 0, user rebooted ~21:30 → P3 21:37: official 2026-09-08 `iTunes64Setup.exe` contains only 2 MSIs (7z-verified; AAS merged into iTunes64.msi — see [[apple-itunes-windows-installer-layout]]), installed AMDS64 then iTunes64 (`AUTORUN=0`), both exit 0 → P4 launch test FAILED as above. iTunes 12.13.11.1 + AMDS 20.0.0.35 registered, AMDS service Running/Auto, Bonjour intentionally absent (not in bundle). **GATE 4 reported — awaiting Phase 5 go**: kill frozen pid 7384 → rename `%LOCALAPPDATA%\Apple Computer\iTunes` to `.bak` → relaunch + repoll; if still hung, procmon `/AcceptEula /Quiet /Minimized /BackingFile C:\Temp\apple\hang.pml` over a 60 s launch then `/Terminate` + CSV, report last 50 iTunes ops + ops with Duration > 5 s; also planned read-only checks: owning PID of the two 27015 sockets and the AMDS service's own thread state.
